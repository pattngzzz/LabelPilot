# LabelPilot

LabelPilot 是一个可复用的本地半自动图像标注工具，支持目标检测、实例分割、语义分割、手部姿态和 OCR 文字标注。通过模型预标注、人工修订与审核、数据集导出，组织可重复使用的标注流程，不绑定特定业务、数据集或模型权重。

## 主要功能

- **本地多项目管理**：通过文件选择窗口接入图片或文件夹，按项目管理任务类型、类别、模型和标注；支持批次筛选、重新扫描与断点续标。
- **交互式标注**：大画布、缩放和平移、快捷键绘制、标签弹窗、对象编辑、撤销与保存历史。
- **模型辅助**：YOLO 单张 / 批量预标注、同类别重复框过滤、SAM3 文字提示与按框生成轮廓；模型结果需人工审核。
- **审核与质量检查**：待审核队列、逐框快审、相似图片筛选、连续帧辅助、疑点复核和导出预检。
- **可配置导出**：多种训练格式、训练 / 验证 / 测试集划分、训练集增强、本机文件夹输出、后台进度与增强缓存。
- **本地训练与对比**：支持的视觉任务可从已审核数据启动训练；目标检测支持冻结盲测集与模型对比。OCR 模型需在外部单独训练。

## 支持的任务

在“新建项目”时选择任务类型。任务类型随项目保存，不会因为切换图片文件夹而自动改变。

| 任务 | 标注方式 | 导出格式 |
| --- | --- | --- |
| 目标检测 | 矩形框、多边形、YOLO 预标注，可用 SAM3 补轮廓 | YOLO、COCO、Labelme |
| 实例分割 | 手工轮廓、分割模型预标注、检测框 + SAM3 轮廓 | YOLO、COCO、Labelme |
| 语义分割 | 多边形、画笔、橡皮及类别掩膜 | 单通道 PNG 掩膜、`dataset.yaml` |
| 手部姿态 | 每只手 21 个关键点，支持可见性与遮挡状态 | YOLO Pose、COCO Keypoints |
| OCR 文字与读数 | 可旋转矩形 / 多边形文字区域、原文、可读性及可选字段属性 | PaddleOCR、Labelme |

目标检测和实例分割导出时可选择“检测框”或“实例分割”用途：检测用途将轮廓转换为外接矩形，分割用途要求所有对象具有有效轮廓，缺少轮廓时阻止导出，不静默丢弃对象。用途转换不修改数据库中的原标注。

语义分割按像素保存类别：背景为 0，前景按类别顺序从 1 开始；后绘制区域覆盖先前区域，橡皮擦回背景。手部关键点可见性为 0（未标注）、1（遮挡）、2（可见）。

## 环境配置

### 基础环境

| 项目 | 说明 |
| --- | --- |
| 操作系统 | 启动脚本与系统文件选择流程面向 Windows 本机桌面使用 |
| Python | 推荐 Python 3.11，为工具建立独立虚拟环境 |
| SQLite | 使用 Python 自带的 SQLite，需支持 JSON 函数，用于轻量队列统计 |
| 浏览器 | 支持 Canvas 的现代浏览器，建议使用 Chrome 或 Edge |
| 文件选择 | Python 环境需提供 Tk / tkinter，服务须运行在可显示窗口的桌面会话中 |
| GPU | 基础标注不要求 GPU；模型推理和训练的 CPU / CUDA 支持取决于所用模型、PyTorch 与驱动环境 |

核心依赖见 `requirements.txt`：FastAPI、Uvicorn、Pillow、NumPy、OpenCV 和 Ultralytics。SAM3 为可选独立环境，不包含在基础依赖中；不使用模型辅助时无需配置 SAM3。

### 安装依赖

克隆或下载本仓库，在仓库根目录打开 PowerShell：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

也可使用已有 Python 环境安装相同依赖。需要 GPU 时，另行安装与显卡驱动匹配的 PyTorch / CUDA 运行环境，并用同一解释器启动工具；安装基础依赖不等于已验证 CUDA 可用。

### 启动与停止

推荐显式指定解释器后使用启动器，避免多环境机器选错 Python：

```powershell
$env:LABELPILOT_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

启动器自动打开浏览器，默认地址为 `http://127.0.0.1:8765`。也可双击 `start.cmd`，但应先确认其选用的解释器已经安装依赖。修改端口或不自动打开浏览器时，为 `start.ps1` 添加 `-Port 8767` 或 `-NoBrowser`。

不使用启动器时可直接运行，再手动打开上述地址：

```powershell
.\.venv\Scripts\python.exe run.py --port 8765
```

保持启动窗口打开，按 `Ctrl+C` 停止服务。默认仅监听 `127.0.0.1`，不提供局域网或公网访问。更新后端代码后，需先保存修改、等待后台任务完成，再关闭旧服务并重新启动；刷新网页不会替换已运行的后端。

## 基本使用

1. **新建项目**：点击左上角“＋ 选择图片”，选择任务类型，通过“选择图片文件”或“选择文件夹”打开系统选择窗口。文件模式只接入明确选中的图片；文件夹模式递归扫描子目录。可选配置已有标注目录、预标注目录、类别文件与模型。
2. **设置类别**：输入有序类别，或导入 UTF-8 的 `classes.txt` / `class_map.json`。类别名称原样保存，不自动翻译；顺序对应类别 ID，不能为显示方便随意排序。OCR 类别留空时默认使用 `text`。
3. **标注与修订**：直接绘制，或先运行模型预标注，再检查位置、类别、漏标与重复目标。按 R 后单击起点，移动鼠标，再单击终点完成框选，无需长按拖动；框旁弹窗可选已有标签或创建自定义标签。
4. **保存与审核**：保存草稿保留修改；按 E 保存并审核当前整张图片，再进入下一张。A / D 翻页会暂存修改，但不等于审核。无对象图片需明确确认后才作为已审核空图。
5. **导出数据**：选择当前项目的批次、审核范围、格式、划分和增强选项，指定本机输出文件夹后启动导出。

项目之间独立管理标注。切换同一项目中的批次或重新扫描文件夹，不会清空该项目已保存的数据；导出范围取决于当前项目及导出筛选，不只是当前打开的一张图片。新增外部图片或标注后可点击队列的“↻”重新扫描。

### 类别管理

右侧标签栏支持自定义标签、导入标签和导出标签。导出的 `classes.txt` 为每行一个名称，行序对应从 0 开始的类别 ID，可供其他项目复用。导入会保留已有类别和 ID，跳过重复名称，将新类别按文件顺序追加；这是类别表导入，不是图片标注文件导入。

仅未被当前标注、历史版本或源标注引用的类别允许删除。删除后剩余类别按原顺序重新编号，需要重新完整导出，并使用匹配的模型；不要混用新类别表与旧标签文件。新增类别不会让旧模型自动获得识别能力。

### 常用快捷键

输入文本、打开对话框等状态下，相关全局快捷键会暂停，避免误触。

| 快捷键 | 功能 |
| --- | --- |
| R | 矩形工具；十字虚线延伸至画布边缘 |
| P | 逐点绘制多边形，至少三个顶点，点击首点或按 Q / Enter 闭合后选择或创建标签；OCR 不限四点 |
| Q / Enter | 完成多边形，或在标签弹窗中确认当前选择；文字输入框内正常输入 |
| V | 选择、移动与调整对象 |
| Z / X | 选中矩形或四角框后，左旋 / 右旋 1°；按住 Shift 每次旋转 5°，长按可连续旋转 |
| A / D | 上一张 / 下一张，不自动审核 |
| E | 保存、审核当前图片并进入下一张 |
| Ctrl+S | 保存草稿 |
| Ctrl+Z / Ctrl+Shift+Z | 撤销 / 重做 |
| Delete / Backspace | 删除所选对象 |
| Esc | 取消当前绘制或选择 |
| F / 空格拖动 / 滚轮 | 适应画布 / 平移 / 缩放 |
| Tab | 切换大画布布局 |
| B / X | 语义分割画笔 / 橡皮 |
| K | 添加手部关键点标注 |

旋转以框中心为轴，保持边长、标签及 OCR 原文等属性；允许超出图片边界，画布和保存均保留完整四角，不裁切或缩放标注。矩形旋转后仍是矩形，八个手柄沿框自身方向调整尺寸，不会变成自由多边形；旧版带角度且符合矩形几何的四点框也按矩形交互。OCR 导出保留矩形四角；Labelme 因格式限制仅在导出副本中用多边形表达旋转矩形，重新导入仍可按矩形操作。普通 YOLO 目标检测导出图像范围内的轴对齐外接框，不是 OBB 格式；YOLO 分割遇到越界顶点会提示调整或改用保留四角的格式，不影响保存。语义分割中的 X 仍为橡皮。

## 模型辅助

### 检测与 OCR 预标注

在模型设置中选择可信的本地 `.pt` 文件，或选择文件夹后从扫描结果中确定权重，保存配置后使用。任务、类别顺序和关键点结构须与项目匹配；模型可覆盖完整类别表，或覆盖顺序一致的类别前缀。实例分割项目允许先用检测模型定位，再补全轮廓。

单张预测采用后进入未保存标注，需核对并保存；批量预标注仅处理未开始图片，不覆盖人工标注、草稿或已有模型结果。批量任务可查看进度与取消，结果不会自动成为已审核数据。

预标注在模型 NMS 后按同类别 IoU 过滤重复矩形框，默认阈值为 0.65，可在界面调整；不是“每类只保留一个框”，允许多个真实同类目标。已有模型结果可用“清理待审核重复框”检查，人工对象和已审核图片不参与自动清理。

OCR 项目使用隔离的 PaddleOCR 运行环境，不读取或替换目标检测项目的 YOLO 权重。Windows 可在独立 Python 3.11 环境安装 `paddlepaddle-gpu==3.2.0`（按 Paddle 官方 CUDA wheel 索引）和 `paddleocr==3.2.0`；CPU 用户可安装对应的 PaddlePaddle CPU 包。将 `ocr_runtime.example.json` 复制为 `data/ocr_runtime.json`，配置独立环境的 `python.exe`、本地模型缓存目录与 `gpu:0` / `cpu` 设备。OCR 面板可查看运行状态和切换设备；首次运行会下载 PP-OCRv5 server 检测与识别模型到缓存目录。单张结果先预览，批量任务只处理未开始图片；结果以“模型待审核”保存，必须核对文字框和原文后再确认。

### SAM3 分割辅助（可选）

检测和实例分割项目可在画布打开“SAM3 辅助”，通过文字描述或已有检测框生成轮廓，也可批量按框生成候选。批量候选独立保存，需读取并人工采用，不自动替换标注或改变审核状态。关联框的候选采用后替换对应框，避免同一对象重复计数；未找到轮廓时保留原框。

SAM3 需要单独准备运行环境和权重，在面板中配置解释器、后端、模型路径与设备。通用配置模板见 `sam3-config.example.json`，保存后的本机配置位于 `data/sam3/config.json`。

| 后端 | 环境与模型要求 |
| --- | --- |
| ONNX | 独立环境需安装 `onnxruntime-gpu`、`onnx`、`tokenizers`、`opencv-python-headless`；CUDA 运行还需兼容的 PyTorch / CUDA DLL。选择包含三个 SAM3 编码 / 解码模型及配套文件的目录 |
| PyTorch | 在独立环境中安装 SAM3 源码、相应依赖及 OpenCV，选择该环境的解释器与 `.pt` / `.pth` checkpoint |

ONNX 模型目录必须包含 `sam3_image_encoder.onnx`、`sam3_language_encoder.onnx`、`sam3_decoder.onnx`、配套 `tokenizer.json` 以及模型引用的全部外部张量文件，不能只复制单个 ONNX 文件。权重由使用者自行获取并遵守相应许可。

配置为 CUDA 时，无法启用 CUDA 会报错，不会静默切换整套模型到 CPU。SAM3 与 YOLO 推理 / 训练有显存互斥保护；使用结束后可在面板释放 SAM3 显存。候选仅保留外轮廓，有内部孔洞等情况需人工修正；速度、显存和效果取决于实际环境与图片。

## OCR 文字与读数标注

新建“OCR 文字与读数”项目，可接入原图或已裁出的文字 / 面板图片。通常用 `text` 表示文字区域，将实际文字录入原文字段，不要把每个读数都创建成类别。

- 用 R 框出一行文字或一个数值单元，选中后可用 Z / X 旋转；不规则文字区域用 P 沿边缘依次标点，至少三点，点击首点或按 Q / Enter 完成，不限四点。弹窗提供区域放大预览、原文、可读性和字段角色，选中后可在右侧继续编辑；多边形不能交叉、重叠或退化。
- 原文与十进制数值分开保存，保留前导零、尾随零、小数点、负号和单位；数值、单位、字段、通道及父对象 ID 可选填，不自动推断。
- 完整可读区域必须填写原文才能审核；部分可读 / 不可读区域应标明可读性，不补造数字。黑屏或空白需明确确认无文字，不能当成读数零。
- PaddleOCR 导出包含检测标签和完整可读区域的识别裁剪；Labelme 导出保留 OCR 属性。裁剪继承原图的数据集划分。
- OCR 导出可选择专用轻量增强、光照变化、轻度画质扰动或全部三种方案；每种方案每张训练原图额外生成 1–3 张，仅增强已审核训练集，保留原图，验证 / 测试集不增强。方案不镜像、不旋转、不裁切，文字顶点、原文和属性保持不变；增强图保存为 PNG，PaddleOCR 识别裁剪从对应增强图重新生成。增强副本并非逐张人工审核，细小文字需抽查可读性；支持增强缓存和增量导出，配置变动时重建受影响的训练样本。

OCR 项目支持本地 PaddleOCR 文字检测与识别预标注，以及人工校对和 PaddleOCR 格式导出；OCR 模型训练仍需使用导出的数据另行完成。目标检测权重不能直接作为文字识别权重使用。

## 数据集导出

打开“导出数据集”，先查看预检中的图片数、对象数、空图和类别分布，再设置：

1. **数据范围**：选择批次和审核范围，默认仅导出已人工确认的数据；未保存的画布修改不参与导出。
2. **格式与用途**：按任务选择对应格式，检测 / 实例分割项目再确认标注用途。
3. **集合划分**：设置训练 / 验证 / 测试比例及随机种子，默认 80% / 10% / 10%；比例之和须为 100%，训练集大于 0，验证或测试可为 0，也可取消划分。
4. **分组策略**：可按任务清单来源组、原图文件夹或图片随机划分。相同来源组不跨集合；按目录划分只有在目录能代表来源时才有隔离意义。连续帧不宜简单随机划分。
5. **增强与并行**：按需选择支持的增强方案、数量、种子和并行数。
6. **输出位置**：点击“选择导出文件夹…”打开系统窗口，再点击“导出到文件夹”。默认每次创建唯一子目录；勾选“只导出新增或修改的数据（增量合并）”后，可直接选择已有数据集目录继续写入。导出不会删除数据库标注。

导出在后台执行，界面显示阶段、百分比、已处理图片数、速度及估计剩余时间，完成后显示完整路径。可关闭窗口继续标注，再次打开查看进度。任务建立标注与类别快照，启动后新保存的修改留待下一次导出。

导出前的预检也在后台只读快照上运行，显示当前检查阶段、处理数量与耗时，不长期占用标注保存锁。修改选项时停止过期预检，仅保留最新设置；可点击“停止预检”，关闭弹窗也会停止预检，不影响已启动的正式导出。预检后继续保存标注时，正式导出仍会检查数据版本，必要时要求刷新预检。

常用输出结构：

- **YOLO**：`images/train|val|test`、`labels/train|val|test` 和 `dataset.yaml`，按用途生成检测、轮廓或关键点标签。
- **Labelme**：`annotations/train|val|test` 中保存逐图 JSON，对应图像副本及对象属性。
- **COCO**：按启用的集合生成 `annotations/train.json`、`val.json`、`test.json`。
- **PaddleOCR**：`det/*.txt` 为图片路径与原始矩形四角 / 多边形顶点及原文，`rec/*.txt` 为识别裁剪路径与原文；`recognition/` 保存无损 PNG，凸四点区域作透视校正，其他多边形按最小外接旋转矩形裁剪并将轮廓外填白，不修改原图或原标注。`annotations/` 保留完整 OCR 属性。部分 / 不可读区域以 `###` 忽略，不生成识别裁剪；确认无文字图保留空检测标签。

`export_manifest.json` 记录来源、版本、划分及增强信息。比例作用于原图，增强仅增加训练集数量；训练集原图数不等于整个数据集原图数。增强图不增加真实场景多样性，来源未知时不能仅凭随机划分的分数认定模型能够泛化。

### 导出增强

当前增强用于目标检测和实例分割，默认关闭。启用时须只导出已审核数据、包含原图副本并启用集合划分；先划分原图，仅增强训练集，验证和测试集保持原样。

| 方案 | 处理与注意事项 |
| --- | --- |
| 轻量通用 | 小幅亮度、对比度和色彩变化，不改变几何位置 |
| 光照变化 | 较大范围明暗与色彩变化 |
| 画质扰动 | 轻微模糊与 JPEG 压缩，小目标和细字需谨慎 |
| 水平翻转 + 轻量变化 | 镜像并同步变换坐标，不适合左右方向或文字有语义的情况 |
| 图片旋转 | 90° / 180° / 270° 整角旋转，同步坐标及宽高，不裁切画面 |
| 全部方案（分别生成） | 五种方案分别从原图生成，不连续叠加 |

每张训练原图可按每种方案额外生成 1–3 张；全部方案每方案 1 张时，共额外生成 5 张，连同原图为 6 张。旋转生成 3 张时覆盖三个角度。增强种子决定随机参数与角度顺序，和集合划分种子独立；相同输入、参数和软件环境可复现结果。

导出校验图片、对象数量、类别、属性和变换后的坐标，失败时中止，不静默丢框。增强只写导出目录和缓存，不新增数据库标注、不改变审核状态。OCR 不启用这些增强，避免文字镜像或方向变化。

### 增量合并

- 直接选择包含本工具生成的 `export_manifest.json`、`classes.txt` 及对应图片 / 标注结构的数据集根目录，不要选择它的上一级。未找到数据集时创建首次独立导出；有数据集文件但缺少有效清单时拒绝合并。
- 以目标数据集清单为基准，不按当天时间筛选：新保存的数据追加，标注版本、内容或文件变化的数据更新，未变的图片及增强副本跳过。预检显示新增、修改、跳过数量，后台进度只计算本次处理量；完成统计显示合并后的总量。
- 保持历史类别编号，当前新类别追加到 `classes.txt` 和对应配置 / 格式元数据；历史类别不自动删除或重排。旧图片保持 train / val / test 归属，新增同来源图片继承已有分组，新的比例和种子仅用于分配新图片，实际总比例不一定等于设置比例。
- 支持 YOLO、Labelme、COCO、PNG 掩膜和 PaddleOCR。同步更新 `dataset.yaml`（适用格式）、汇总标签与导出清单；标注改变时同步重建相关增强 / OCR 裁剪并移除失效副本。增强参数改变需将所有历史原图纳入当前范围；项目、格式、标注用途、是否包含原图、是否划分或划分单位不兼容时，需要另建完整导出。增量与清洗不能同时启用。
- 增量不是镜像同步：范围外历史数据保留，不因切换批次、取消审核或删除源文件而自动移除。需要严格反映当前筛选结果、重新划分全部旧图或清除历史类别时，请完整导出到新目录。
- 首次复用旧版导出需要迁移校验，可能较慢。后续依据标注内容与文件大小 / 修改时间快速判断，变化时核对 SHA-256；这不是每次全量重新哈希的外部篡改审计。新增及重建文件仍执行完整性校验。
- 同一服务会话内使用有界内存指纹缓存，文件路径、大小、修改时间及文件身份未变时复用 SHA-256，减少切换增强方案、重复预检及正式导出准备时的重复读取；变化时重新计算，类别、标注坐标、配对和清单结构仍逐次检查。缓存随服务重启失效，不写入或修改源文件。
- 先在同盘临时目录写入并校验，合并时备份待替换文件并最后更新清单；正常异常或取消时自动回滚。不要同时手动修改或训练读取正在合并的数据集。若进程 / 系统异常退出留下 `.labelpilot-export.lock` 或 `.lp-*.part`，请保留恢复目录、检查备份后再继续，不要直接删除恢复文件。

### 并行与缓存

文件夹导出默认自动选择最多 4 路图片准备任务，也可选 1 / 2 / 4 / 8 路；大图或内存紧张时可降低并行数。增强共享原图解码，并复用 `data/export_cache/` 中的有效缓存。

缓存根据原图指纹、标注、增强参数、算法与 Pillow 版本区分；复用仍执行完整性校验，失效或损坏时重新生成。默认上限 10 GiB，可在界面关闭复用，不影响原有导出或标注。实际加速效果取决于存储、CPU、内存和图片大小。

## 训练、对比与自动流程

- **一键清洗**：检查当前范围内的已审核图片、结构问题及精确重复，输出独立数据集和排除清单，不删除源文件。近似图片或语义误标仍需人工判断。
- **一键训练**：目标检测、实例分割、语义分割和手部姿态可创建清洗后的训练快照，配置权重、尺寸、轮数、批大小和设备，查看日志与进度，完成后下载权重或设为预标注模型。权重须匹配任务；语义分割需要支持相应模型的 Ultralytics 环境。
- **固定盲测与模型对比**：用于目标检测，在同一冻结数据和推理设置上比较模型，查看逐类召回、漏检和误检；外部权重的训练数据重叠情况不一定可核实。
- **辅助与自动流程**：按任务提供连续帧传递 / 插值 / 跟踪、相似筛图、疑点复核、目录收图、审核分流等；检测训练验收可比较固定基线与候选模型，启用候选模型需要确认。

模型建议、跟踪结果和自动流程不替代人工审核。未经过独立来源测试，不能将内部验证成绩视为新场景效果保证。

## 数据保存与安全

以下路径均相对于工具根目录，属于本机状态，不随源码仓库同步：

| 路径 | 内容 |
| --- | --- |
| `projects.json` | 本机项目、数据路径、类别与模型配置 |
| `data/workbench.sqlite3` | 已保存标注、审核状态、版本与历史快照 |
| `data/sam3/` | SAM3 本机配置及相关文件 |
| `data/training/` | 本地训练快照、日志与产物 |
| `data/blindsets/` | 冻结的盲测数据 |
| `data/export_cache/` | 可复用的增强缓存 |
| 用户选择的导出目录 | 独立导出数据集；历史 ZIP 接口仍保留兼容 |

- 原图、原始标注和已有预标注只读引用，新修改保存在工具数据库；导出不会清空标注或自动覆盖源标签。
- 原图指纹、尺寸与保存版本检查用于避免套错图片或并发覆盖；含 EXIF 旋转的图片需先生成方向归一化的独立副本再标注。
- 备份时先停止服务，再备份 `projects.json` 和整个 `data/`，并保留或另行备份外部原图及源标注。不要在运行中只复制 SQLite 主文件而遗漏 WAL。
- 工具没有账户系统或云同步，使用本机会话和同源限制；不要将端口暴露到公网。只加载可信权重，PyTorch 模型可能执行反序列化代码。
- Git 仅管理源码、启动入口、测试与文档。数据、数据库、缓存、导出、权重、个人路径配置与凭据不应提交；代码同步不等于数据备份。

## 开发验证

日常使用不需要 Node.js。运行 Python 测试需额外安装开发依赖，以下为任务类型和工作台的针对性检查示例：

```powershell
.\.venv\Scripts\python.exe -m pip install pytest httpx
.\.venv\Scripts\python.exe -m pytest tests/test_task_types.py tests/test_workbench.py -q
```

浏览器集成测试另需支持 `node:test` 的 Node.js 和本机 Chrome；可通过 `LABELPILOT_CHROME` 指定浏览器路径：

```powershell
$env:LABELPILOT_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
node --check static/app.js
node --test tests/test_browser.cjs
```

浏览器测试使用临时数据、独立端口和浏览器配置，不写入真实项目。测试通过不等于模型在真实数据上的精度、泛化效果或长期稳定性已经验证。
