# LabelPilot 本地半自动标注工作台

## 启动

双击本目录的 `start.cmd`。启动窗口保持打开，浏览器会自动打开 `http://127.0.0.1:8765`。
关闭服务：在启动窗口按 `Ctrl+C`。服务仅监听本机，不开放局域网访问。

当前默认解释器是 `D:\Miniconda3\envs\key_action_py311\python.exe`，使用已有 CUDA / Ultralytics 环境，没有安装或升级依赖。可以在 PowerShell 中通过 `$env:LABELPILOT_PYTHON='你的python.exe'` 切换解释器；换端口可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Port 8767`。

## 推荐流程

1. 选择批次或审核状态，点击图片。原有框及描述、属性、group_id 会保留。
2. 点击“模型预标注”，检查本地模型路径、置信度、IoU 和输入尺寸。模型 ID / 名称必须和项目逐项匹配。
3. 推理后选择“追加对象”或“替换当前对象”。这里只改变当前画布，尚未保存；替换可以撤销。追加不会自动去重，须检查重叠框。
4. 按 **R**，单击起点后松开，移动鼠标预览矩形，再单击对角终点完成框选，不需要长按拖动。框旁自动弹出标签窗口，默认聚焦确认按钮，按 **Q / Enter** 使用当前标签，也可点击已有标签；点击输入框输入自定义名称后，按 Enter / 点击“创建并使用”。输入框内的 q / Q 正常输入文字，不触发确认；确认后才加入当前标注。Esc 或“取消框选”可取消，不会新增对象。V 选择、拖动、调整框角或边；P 逐点画多边形，**Q / Enter** 完成。**A 上一张、D 下一张**，有修改会自动保存为草稿，翻页不会自动审核。右侧可以改标签、描述和难例。多边形可拖动顶点。
5. “保存草稿”独立保存修改；按 **E** 或点击“确认并下一张”会保存、将当前图片标记为已审核，再进入下一张，表示你已检查当前整张图片。长按 E 不会连续审核多张；输入标签或打开弹窗时不会触发。历史人工标注和模型结果不会自动变为“已审核”。零检测也不会自动成为负样本，空标注审核需要明确确认。
6. 导出时默认仅纳入已人工确认的图片。可选 YOLO 检测、Labelme / X-AnyLabeling、COCO；可自行设置训练 / 验证 / 测试集比例，默认 80% / 10% / 10%，也可取消划分。可选训练集数据增强，默认不启用。所有导出包含类别、来源及划分清单。

界面默认采用紧凑布局，优先给图片分配空间。按 **Tab** 或点击工具栏的“大画布”，可收起顶部和两侧面板，再按一次恢复；偏好会在本机浏览器保留。滚轮以鼠标位置为中心缩放，F 适应画布，空格拖拽平移。

按 **R** 进入矩形框模式后，十字光标的上下左右各有一条延伸至画布边缘的虚线，随鼠标移动，辅助对齐框选位置；图片缩放 / 平移不改变辅助线与光标的对齐。鼠标离开画布、切换工具、打开框选标签窗口或按住空格平移时隐藏。辅助线仅用于界面显示，不写入标注或导出数据。

### 自定义标签

在右侧“输入自定义标签”中输入原始名称，按 Enter 或点击“+”。新增标签会成为当前绘制标签；如果已经选中对象，也会把该对象改为此标签，随后需要保存。重复输入已有名称只会选用已有标签，不会产生重复 ID。

标签名称在画布、列表、选择框和导出中原样保留，不自动翻译成中文。新标签追加在类别表末尾，不重排原有 ID。首次添加时，工具将当前有序类别独立保存到自身 `projects.json`，并记录原类别映射路径，不改动源 `class_map.json`。

右侧标签栏的“↓ 导出标签”可单独下载当前项目完整的 `classes.txt`，包含已确认添加的新类别，即使尚无图片使用该类别也会导出。文件为 UTF-8、每行一个类别，行序对应从 0 开始的类别 ID，不翻译、不排序；未提交的标签输入不计入。导出无需保存或审核图片，不改变标注与审核状态，也不覆盖原先导入的类别文件。后续建立新项目时，在“或类别映射文件（优先）”中使用下载文件的完整路径即可复用；文件保存位置由浏览器下载设置决定。

追加标签后原基线仍可为已有类别预标注，但不会自动识别新增类别。新增类别需要人工标注或后续训练支持；模型原有类别 ID / 名称仍须与项目对应，错序和改名会被拒绝。

### 选择和切换模型

在模型设置中点击“选择文件”，通过本机文件浏览窗口进入文件夹并点击 `.pt` 权重；也可点击“选择文件夹”，进入目标目录后点击“选择此文件夹并查找模型”，从包含子文件夹的候选结果中明确选择一个模型。不再需要手动复制完整路径，仍保留直接输入路径的方式。

支持磁盘切换、输入文件夹路径、上一级目录和中文路径。浏览只返回文件名、路径和大小，不上传、复制、加载或执行权重；取消不会改变模型。扫描跳过链接 / 联接目录，最多检查 20,000 个目录项、列出 200 个模型，搜索预算为 5 秒；遇到权限或数量限制会提示结果可能不完整，应缩小目录后继续查找。

选择后路径显示为“尚未保存配置”，点击“保存模型配置”或发起预标注后生效。下次推理按新路径重新加载模型并校验类别；单纯切换配置不改动当前标注。存在运行中或等待中的模型任务时，先等待结束或取消任务，再切换权重。只选择可信的本地 Ultralytics `.pt` 检测权重，文件后缀本身不能证明来源可信或类别兼容。

## 批量预标注

左侧星形模型按钮进入设置，指定当前批次 / 搜索范围和数量上限，点击“批量预标注”。只处理**未开始**图片，不覆盖人工标注、历史预标注或草稿。状态筛选不会扩大范围，也不会改变只处理未开始图片的保护。

任务在后台串行处理；界面可继续标注其他图片。可以取消，当前推理结束后停止。重启后未完成任务记为中断；重新启动批量任务时会跳过已保存结果，不自动伪造完成或审核状态。

## 接入新项目与后续模型

点击左上角“＋ 选择图片”，在新项目窗口中点击“选择图片文件”或“选择文件夹”，直接弹出 Windows 系统原生选择窗口，确认后自动回填完整路径，不需要手动输入地址；仍保留手动填写目录的方式。图片文件支持同文件夹多选（JPG / JPEG / PNG / BMP / WEBP / TIF / TIFF），只导入明确选中的图片，重新扫描或重启不会把同目录其他图片加入该项目。取消或选择失败不会改变已有选择。文件夹模式递归读取其中及子目录的图片，也可点击“改为整个文件夹”退出文件列表模式。选择后填写项目名称和有序类别，再点击“建立项目”；新项目与原项目独立，原图只读引用，不上传、不复制、不覆盖已有标注。

还可填写 Labelme 标注目录、预标注目录、有序类别和可信本地 `.pt` 检测模型。华聚式项目可以额外指定任务清单；指定图片文件与任务清单不能同时使用。系统选择窗口由本机 Python 的标准库 Tk 在独立进程中打开，服务须运行于本机桌面；窗口未出现在前台时可查看任务栏。一次只打开一个选择窗口，五分钟未完成会关闭并提示重试；选择窗口打开期间不能重复选择或建立项目。文件列表项目最多选择 10,000 张图片，所选文件必须在项目图片目录内，缺失或非法路径会拒绝导入，不会自动改为导入整个目录。

类别输入顺序就是模型类别 ID，不能为了显示方便随意排序。支持 `classes.txt` 或带 `names` 列表 / ID 字典的 JSON。模型可以覆盖完整标签表，或覆盖其顺序完全一致的前缀（末尾为人工新增标签）。只有图片目录和类别是必填项。新模型训练好后，在模型设置中切换权重即可；工具不负责训练或证明模型准确率。

新增原图或外部标注后，点击图片队列右上角“↻”重新扫描；本工具已保存的独立版本不会覆盖回源文件。存在重名图片且标注对应关系不唯一时会拒绝自动匹配，需拆分目录 / 项目或使用唯一文件名。

## 导出数据集划分

在“导出”窗口勾选“按比例划分训练 / 验证 / 测试集”，设置三个百分比及随机种子后生成 ZIP。比例之和必须为 100%，训练集必须大于 0；验证或测试集可设为 0。相同图片集合、比例和随机种子可复现划分，不依赖图片列表顺序。图片张数按比例取整，每个非零集合至少保留 1 张，图片不足时会拒绝导出；完成后显示三个集合的实际张数。划分只针对所选批次及审核条件筛选后的图片，不改变数据库审核状态，不移动原图。

- YOLO：图片和标签分别写入 `images/train|val|test`、`labels/train|val|test`，生成带相对路径与原始类别名的 `dataset.yaml`。包含图片且训练 / 验证集非空时，解压后可作为 Ultralytics 检测训练数据集使用；训练时指定解压后 `dataset.yaml` 的路径。验证集为 0 或仅导出标签时，训练前需另外配置验证数据或补齐图片。
- Labelme / X-AnyLabeling：逐图 JSON 写入 `annotations/train|val|test`，`imagePath` 指向对应图片副本，保留原有属性。
- COCO：按集合生成 `annotations/train.json`、`annotations/val.json`、`annotations/test.json`，零比例集合不生成文件；`file_name` 相对解压后的数据集根目录。
- 取消划分：保留原先的平铺导出目录。`export_manifest.json` 记录比例、种子、实际张数和每张图片归属；不划分时记录为 `unassigned`。

当前按图片随机划分，**不保证同源、视频帧、重复图片隔离，也不保证每类样本的分层比例**。来自同一视频或拍摄组的相似图片可能跨集；训练前应依据清单中的来源组另行检查泄漏，不能仅凭比例认为得到独立测试集。工具不会因此自动删除或合并图片。

## 数据保存与保护

- 图片、任务清单、原生标注和旧预标注只读。新修改保存在本目录 `data\workbench.sqlite3`，包含每次保存的完整版本以及首次导入快照。
- 原图 SHA-256 / 尺寸校验、原生标注首次保存前指纹校验和版本冲突检测，防止错误套图或多窗口覆盖。
- 导出 ZIP 保存在本目录 `exports`。模型设置、任务状态、推理与绘图库缓存均放在本工具目录中。
- 建议关闭服务后备份整个 `data` 目录和 `projects.json`。不要仅在运行中复制一个 SQLite 主文件而漏掉 WAL 文件。
- 没有账户和云同步；本地会话令牌、同源校验和 Host 限制用于防止外部网页操作本地服务。不应自行把端口暴露到公网。
- PyTorch 权重可能执行反序列化代码，只加载你信任的模型；不会按模型名自动下载权重。

## 当前边界

支持检测框和多边形，不包含 SAM 点击分割、旋转框、关键点、多人协作和训练调度。YOLO 检测导出遇到多边形会报错，不会悄悄转成外接框；多边形请选择 COCO / Labelme。含 EXIF 旋转的原图会阻止编辑，需先建立方向归一化的独立副本。

真实人工标注准确性、模型独立泛化指标、长期批量运行稳定性：`NOT_PROVEN`，需要真实人工审核 / 独立验证集 / 长时间运行证据。预标注减少多少人工时间也尚未测量。

## 导出时数据增强

在导出窗口的“导出时数据增强”选择方案，设置每张训练图片**每种方案额外生成 1–3 张**及增强随机种子。默认“不增强”，原有导出行为不变。五种方案均基于已有 Pillow，不增加生产依赖：

| 方案 | 处理 | 适用与限制 |
| --- | --- | --- |
| 轻量通用（推荐） | 亮度 0.85–1.15，饱和度、对比度 0.90–1.10 | 保守起步，不改变几何位置 |
| 光照变化 | 亮度 0.65–1.35，饱和度、对比度 0.80–1.20 | 模拟明暗和色彩变化，不做翻转 |
| 画质扰动 | 亮度、对比度 0.90–1.10，模糊半径 0.3–0.8 像素，JPEG 质量 65–85 | 模拟轻微模糊、压缩；小目标、铭牌细字谨慎选用 |
| 水平翻转 + 轻量变化 | 左右镜像并同步框 / 多边形坐标，叠加轻量变化 | 仅适合左右无关类别，文字、左右方向有语义时不要使用 |
| 图片旋转（90° / 180° / 270°） | 按逆时针整角旋转，框 / 多边形逐点同步；90° / 270° 交换图片与标注宽高 | 保留完整画面，不裁剪、不缩放；仅适合方向无关场景，文字、重力或朝向有含义时谨慎使用 |

旋转方案由增强种子、原图 ID 和指纹确定三个角度的不重复顺序：设为 1 / 2 / 3 张时取该顺序的前 1 / 2 / 3 个角度，设为 3 即每张训练原图各生成一张 90°、180°、270° 副本；增加数量不会改变已有副本。不支持任意角度旋转，避免引入目标裁切或轴对齐框变松的问题。

选择“全部方案（分别生成）”会让上述五种方案各自从原图独立生成，不会把五种处理连续叠在同一副本上。数量按**每方案**计算：设为 1 / 2 / 3 时，每张训练原图分别增加 5 / 10 / 15 张，保留原图后共 6 / 11 / 16 张；界面实时显示总数。建议全部方案先设为 1，文字、方向类别或特别小的目标不宜直接用全部方案。

增强随机种子决定亮度、对比度、模糊等随机参数及旋转角度顺序。相同原图、种子、方案和软件环境可复现相同副本；换种子可改变随机参数或旋转角度顺序，不表示增强更强或更好；旋转仅有三个角度，不同种子也可能得到相同角度或顺序。默认 42 没有特殊质量含义。它独立于数据集划分种子，单独改变增强种子不会改变原图的训练 / 验证 / 测试归属；全部方案中的每种结果与同种子下单独选择该方案一致。

增强必须勾选“只导出已人工确认”和“包含原始图片副本”，并启用数据集划分；只要训练集时可设为 100 / 0 / 0。先划分原图，再仅对 `train` 生成副本，`val` / `test` 不增强。同一原图及其增强副本不会跨集，但原来不同文件之间的同源 / 重复问题仍需检查。比例作用于原图；例如原图分配 80 / 10 / 10 张，每张训练图额外 1 张，则最终 160 / 10 / 10 张，不会重新划分增强结果。

始终保留原图副本；新增图片为独立 JPEG，透明图片在增强副本中合成到白底。YOLO 检测、Labelme、COCO 均生成对应标注，类别名称和 ID 不变；YOLO 遇多边形仍拒绝导出。Labelme 保留对象属性，同时将增强副本标记为未单独人工审核，不冒充原始审核结果。写入 ZIP 前会逐张核验原图 / 增强图 SHA-256 与尺寸、对象数量、类别、属性和坐标；无几何变化的方案要求标注点完全一致，水平翻转和旋转则逐点核对变换后的精确坐标，并核对旋转后的宽高。然后回读 YOLO / Labelme / COCO 导出内容，检查对象数量、坐标及图片配对，并检查 ZIP 路径无冲突。任一检查失败就中止并删除不完整 ZIP，不会静默丢框或自动修框。导出清单记录源图片 ID / SHA-256 / 版本、方案、操作参数、随机种子、Pillow 版本和增强后图片 SHA-256，并记录校验通过的图片 / 标注对象数量；同一源文件、参数和环境可复现。每包原图不超过 10000 张，含增强最多 20000 张。

增强只写导出包，不新增数据库标注、不改变审核状态、不写源文件。建议从轻量方案、额外 1 张开始；增强不是新采集数据，也不代表改善泛化，实际训练收益为 `NOT_PROVEN`，需保持独立验证 / 测试集做对比。训练阶段若还启用在线增强，应避免叠加过强。

浏览器测试使用 Node.js 内置测试运行器和本机 Chrome，自动创建临时图片、项目、独立服务端口和浏览器配置，不写入真实项目或标注。可通过 `LABELPILOT_CHROME` 指定浏览器路径。覆盖两次点击画框、标签弹窗、取消、撤销、自定义标签、E 审核保存、失败保护、模型文件 / 文件夹选择、导出比例校验、实际 ZIP 下载及响应式布局。

测试依赖是已有的 pytest / httpx，没有安装新的生产依赖。当前测试环境的 Starlette TestClient 会提示 httpx 兼容弃用警告，但测试通过；为避免影响原有环境，未升级该依赖。

## 版本管理

后续功能迭代完成针对性验证后，创建独立 Git 提交，并推送到已经确认的 GitHub `origin`。远端账号或仓库尚未确认时，只保存本地提交，不推送到其他账号。推送失败或尚未执行时，不视为已同步到 GitHub。

Git 只管理工具源码、启动入口、测试和说明。不提交本机 `projects.json`、原图、人工标注、模型预标注、模型权重、SQLite 数据库、导出包、缓存或凭据。提交前检查暂存文件清单；数据备份仍按“数据保存与保护”单独进行，不能以代码推送替代标注备份。
